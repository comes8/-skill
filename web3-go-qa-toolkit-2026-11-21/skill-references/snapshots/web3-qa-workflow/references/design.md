# Web3 测试设计

## 覆盖矩阵

每行记录需求/规则来源、影响模块、场景、预期、验证来源、优先级、待确认项、用例 ID。一个需求影响多个模块时分别列出独立核对源。按变更缩小执行范围，明确这次不涉及哪些模块及原因。

| 模块 | 常见组合与风险 |
| --- | --- |
| CEX 现货 | 委托类型、有效期、交易对精度与边界、成交与撤单竞争、请求幂等。用 orderId / tradeId 对齐查单、成交、冻结、解冻、费用与流水。区分订单已受理和最终成交。 |
| CEX 合约 | 开平、只减仓、持仓方向/模式、逐仓与全仓、保证金、标记价格及资金费窗口。覆盖部分成交、反向场景和数据延迟，按同一仓位独立核对。 |
| 行情与 WebSocket | 快照与增量、顺序/重复/缺口、断线重连、事件和 REST 查询收敛。先确认序列号是否按频道、交易对或连接定义。 |
| 资金与账务 | 冻结/解冻、资金划转、手续费币种、状态和最终余额、补偿及流水时限。跨服务按订单号/成交号/流水号关联资产主体，金额规则来自项目。 |
| 链上资产 | 链、币种与精度、充值确认、同一转账只入账一次、提现状态和延迟。按项目确认确认深度、唯一事件定位方式、重组及回滚政策。 |
| DEX | quote、deadline、slippage/minOut、网络与合约版本、余额、回执、事件和索引。记录链 ID、块高、交易哈希及合约地址引用，固定 fork 或受控本地测试数据。回执、实际余额和索引是三份独立证据。 |
| 界面 | 表单、状态、提示、交易端与后台一致性。优先按可见业务语义定位。选代表性链路取证，把组合穷举放在接口层。 |
| 性能 | 分开定义吞吐、延迟、错误率、积压及恢复。使用经批准的隔离环境验证约定负载、观测和中止条件。 |

## 跨业务例子

现货部分成交后撤余单。确认交易对和账户初始资产，委托创建后提取 `orderId`。等待已确认的部分成交事件，记录累计成交。撤余后等待终态，并用 `orderId/tradeId` 到成交与账务核对。释放时延、冻结公式、手续费与舍入规则依据项目约定。业务量出错且 HTTP 成功时仍要判失败。

执行计划至少说明模块、顺序或依赖组、失败阻塞规则、数据边界、运行工具和应产出的证据。UI 可用于验收和准备数据，但完成后需要记录实际数据 ID 和独立观察值。测试说明与实际执行状态分开登记。
